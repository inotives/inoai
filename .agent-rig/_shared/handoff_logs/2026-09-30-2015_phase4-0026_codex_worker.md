# Task 0026 unsupported approval variants

Added explicit fail-closed handling for `item/permissions/requestApproval`, `applyPatchApproval`, and `execCommandApproval`. The permissions response grants no requested permissions for the current turn; the legacy responses use the protocol's denied decision with fixed safe text. Each responds before sending a fixed owner notice and recording a non-secret `approval_unsupported` Event. No raw request fields are stored or posted, and no approval controls are offered. Other server requests remain untouched.

The response shapes were checked against the locally generated Codex CLI `0.157.1` protocol and the [official app-server documentation](https://learn.chatgpt.com/docs/app-server). The existing regression now exercises all three variants with token-shaped payloads alongside the two v2 methods.
