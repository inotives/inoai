# Task 0028 worker handoff

Added `runRuntimeTurn` as the Phase 4 runtime-turn boundary. It records one safe Event per attempt and outcome, retries only explicitly proven-safe pre-start/timeout failures up to three attempts with 100/200 ms backoff, buffers the final answer until the stream confirms completion, and returns one typed success or safe failure notice. It does not send to Discord or alter the Phase 5 queue worker/recovery path.

`CodexRuntime` now classifies structured app-server `codexErrorInfo` for `unauthorized` and usage-limit variants without copying raw error messages. Explicit cancellation is distinct from uncertain interruption. Unrecognized failures, process loss, and ambiguous `turn/start` rejection remain uncertain and are never retried. A stopped/error app-server before `turn/start` is explicitly safe to retry. The returned `replaySafe` outcome and durable Events are available for Phase 5's safety gate; a crash after an attempt Event remains uncertain, not proven safe.
