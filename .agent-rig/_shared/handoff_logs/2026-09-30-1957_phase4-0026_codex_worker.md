# Task 0026 fail-closed preview follow-up

Removed the raw command/path/host preview heuristic. For the two v2 approval methods currently handled by the relay, Codex CLI `0.157.1` offers no demonstrably safe, complete preview. The relay now declines each active request before posting any control or persisting request details, records a non-secret `approval_unsupported` Event, and sends/archives a fixed, safe owner notice. The regression covers a token-shaped literal in a command, file root, and network host, plus a request without preview fields. None creates an approval row or actionable controls.

`npm test` passes (58/58), `npm run typecheck` passes, `npm run build` passes, and `git diff --check` passes. No bot credentials or live Discord gateway were used.

**Acceptance gap:** no current CLI `0.157.1` approval shape meets ADR 0003's safe, sufficiently informative preview requirement. Thus the task's positive "one live approval produces controls" and owner-click path cannot be exercised honestly. Existing control-handling code remains, but no current request enters it. Independent review should verify the security fix; the planner should not mark task 0026 done without resolving this acceptance gap. Legacy and permissions approval RPC methods are outside the two v2 methods this relay handles and need explicit protocol decisions if V1 must support them.
