# Task 0074 worker handoff

Implemented incremental, retry-safe, non-blocking BigQuery sync behavior.

## Changes

- Added the local `bigquery_sync_state` table with one durable row per export table, watermarks, retry counters, next-attempt time, and a generic non-secret failure marker.
- Changed export selection to use `updated_at` watermarks with a one-second overlap; repeated rows remain safe through the existing BigQuery source key `(agent_instance_id, source_id)`.
- Advance each table watermark only after that table's upsert succeeds; failed tables retain their prior watermark.
- Added bounded exponential retry (two minutes through one hour), plus local `bigquery_sync_failed`, `bigquery_sync_deferred`, and `bigquery_sync_succeeded` events. Sync-generated events are excluded from the analytics event stream to avoid self-feeding exports.
- Added `BigQuerySyncScheduler` with the configured interval, immediate startup poke, overlap protection, and async shutdown waiting for an active request.
- Added focused tests for watermarks/overlap, retry/defer state and events, and scheduler cadence/stop behavior.
