# Task 0026 blocked: safe approval preview

The 0750 reviewer found that `src/approval-relay.ts` can persist and post a literal credential inside an otherwise simple command such as `echo sk-proj-abcdef`. The current predicate checks characters and credential *names*, not whether arbitrary literal values are secrets. I made no implementation edits in this follow-up; that finding remains open.

I generated TypeScript protocol bindings from the installed Codex CLI into `/private/tmp/inoai-phase4-protocol-0026`. `v2/CommandExecutionRequestApprovalParams.ts` exposes raw `command` and `cwd`, optional `networkApprovalContext`, and best-effort `commandActions`. `v2/CommandAction.ts` shows every variant contains raw `command`; `name`, `path`, and `query` are also arbitrary text. `kind` only distinguishes `command` from `writeStdin`. The protocol provides no complete, demonstrably secret-free command preview. Copying any of those arbitrary fields to SQLite or Discord can leak credentials.

Owner decision needed:

- A: Display only structural enum action kinds/count and trusted project context, while allowing arbitrary approvals. This avoids copying raw literals but gives coarse consent and may hide the action's actual effect, especially for `unknown` actions.
- B: Decline command approvals that lack a complete safe preview, before persistence or posting. This fails closed but means many legitimate arbitrary commands cannot be approved through Discord. It is a material Phase 4 capability gap.

An exact-command allowlist was considered but rejected as conflicting with the project's no wrapper-level tool allowlist boundary. The planner requested a pause for the owner's choice. Task status is `blocked`; no new tests were run because no code changed. The preceding reviewer reported 58/58 tests, typecheck, build, and diff check passing on the still-vulnerable implementation.
