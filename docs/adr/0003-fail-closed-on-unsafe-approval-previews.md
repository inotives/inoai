# Fail closed when a Discord approval cannot be explained safely

Codex app-server requests in CLI `0.157.1` expose arbitrary text and best-effort action fields, not a complete safe preview for the current command, file, network, and permissions approval shapes. Copying those fields to SQLite or Discord could leak credentials; hiding them behind a generic Approve button would not give the owner informed consent. V1 therefore declines every approval request through the live protocol, records only a non-secret outcome, and tells the owner to use local Codex for the blocked action. Discord **Approve**/**Reject** buttons are deferred. This does not change Codex's configured sandbox or approval policy and adds no wrapper command allowlist. Revisit buttons only when a supported preview mechanism passes consent and secret-leak tests.
