# Fail closed when a Codex approval request is lost on restart

Codex CLI `0.157.1` resumes a stored thread after app-server restart but does not reissue an interrupted approval request. SQLite preserves the approval record, not the live JSON-RPC request, and replaying the turn could repeat earlier side effects. Supported command requests can now create pending Discord cards (ADR 0003). On restart, inoai marks pending approvals `failed`, disables their cards, and never approves or replays the interrupted turn from SQLite alone. It redacts any arbitrary preview saved by older local builds; new command cards store only a fixed summary and generic message body in SQLite. It records one safe recovery Event and claims the owner notice before sending: normal startup posts it once, while a crash may omit it but cannot cause a duplicate. Exact-request recovery remains possible only if a future supported runtime mechanism can prove that the same live request survives.
