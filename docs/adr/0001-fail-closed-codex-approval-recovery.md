# Fail closed when a Codex approval request is lost on restart

Codex CLI `0.157.1` resumes a stored thread after app-server restart but does not reissue an interrupted approval request. SQLite preserves the approval record, not the live JSON-RPC request, and replaying the turn could repeat earlier side effects. V1 now declines new approval requests immediately (ADR 0003), so it creates no pending approval controls. If an earlier local build left a pending row or Discord buttons, inoai marks it `failed`, redacts saved previews, makes the controls inert, and never approves or replays the interrupted turn from SQLite alone. It records one safe recovery Event and claims the owner notice before sending: normal startup posts it once, while a crash may omit it but cannot cause a duplicate. Exact-request recovery remains possible only if a future supported runtime mechanism can prove that the same live request survives.
