# Claude permission prompts fail closed like Codex

Claude reports permission prompts with structured tool input (in headless `-p` mode, as `permission_denied` events and `result.permission_denials`), which could support Discord **Approve**/**Reject** buttons. inoai deliberately matches ADR 0003 instead: every prompt is denied, inoai records only a non-secret outcome, and the owner is told to use local Claude for the blocked action. Structured input still carries arbitrary command text and file content, so buttons would reintroduce the consent and secret-leak risks ADR 0003 deferred. The owner's Claude settings (`permissions` rules and `defaultMode`) keep deciding which tools run without a prompt; inoai never adds allow rules, auto-allows read-only tools, or changes the permission mode. The adapter passes `--permission-prompts none`, which only removes the prompt answerer so prompts are denied explicitly; it never loosens the owner's rules. Revisit together with Codex buttons once a preview mechanism passes consent and secret-leak tests.
