# External heartbeat supervisor

inoai will use one user-level macOS `launchd` LaunchAgent to start and monitor the Agent Instance process. The Heartbeat Supervisor owns the restart decision and performs the hourly health check, so operators start one service while the supervisor manages the child process and recovers stale runtime state. A healthy check requires a live child process, a fresh PostgreSQL lease, valid runtime-home lock ownership, and a successful lightweight database query. The interval is fixed at 60 minutes and the database probe has a 5-second timeout. It restarts immediately for a dead child or proven stale local lock, but requires two consecutive database or lease failures before restarting to tolerate a transient outage; `launchd` supplies restart throttling for repeated failures. The first deployment supervises `.inoai-connect-planner`; the command remains configurable through `--connect-dir`. Supervisor restart events stay in `~/Library/Logs/inoai/heartbeat.log`, failures go to `~/Library/Logs/inoai/heartbeat-error.log`, and the restarted `inoai` process emits its normal Discord startup status. The explicit installer resolves the repository and runtime-home paths at install time and renders them into the user-specific plist; repository files contain no machine-specific absolute paths. The plist supports automatic login start and supervisor recovery, but both options are disabled by default until explicitly enabled. Lock recovery reuses the existing process-identity proof and fails closed for malformed or unverifiable locks. A child restart sends `SIGTERM`, waits up to 10 seconds, then sends `SIGKILL` if needed. Repeated child exits restart after 10 seconds, with at most three attempts within five minutes before the supervisor stops and logs the failure. The same supervisor supports foreground execution for debugging and optional `launchd` installation.
