# Memory Reviews run text-only in throwaway sessions

A Memory Review sends archived chat text to the Agent Runtime unattended, and that text can contain quoted instructions. Running it inside the thread's own Agent Session would pollute that conversation's context, and running it with the owner's normal tool policy would turn instruction-like archive text into an unattended injection path (OpenCode's defaults even allow shell). Each review therefore runs in a fresh throwaway session with the runtime's strongest restricting options, the same precedent as the concurrency probes: Claude with all tools disabled, no MCP servers, no session persistence, `--safe-mode` (which drops the owner's CLAUDE.md, skills, plugins, hooks, agents, and auto-memory while keeping subscription sign-in), and `--system-prompt` replacing the default system prompt with inoai's fixed review instructions, so the owner's Claude Code context cannot shape or leak into Recaps; a review whose init still reports memory paths, MCP servers, or tools fails closed; Codex with a read-only sandbox and approval policy `never` (implemented but disabled: a Codex review thread still loads the owner's `~/.codex` MCP servers, which the read-only sandbox does not restrict, and no MCP-off override has been verified with real Codex). These options only restrict a session inoai creates for itself and never elevate the owner's policy. Codex and OpenCode homes skip reviews (recorded as a non-secret Event, cursor unchanged) until a tool-free mode is verified with the real CLI; only Claude reviews run in V1. The model only proposes Recap text and Memory actions (the aggregation step also receives the owner's explicit memory requests that inoai detects with the same rule it validates against); inoai verifies every checkable claim (owner-authored explicit signal, recurrence across prior Recaps, existing IDs, in-range sources, length and secret filters), keeps Manual Memory Entries read-only to reviews, and commits recap, actions, and cursor in one transaction. Because reviews have no side effects before that commit, an interrupted or failed review is safe to rerun.
